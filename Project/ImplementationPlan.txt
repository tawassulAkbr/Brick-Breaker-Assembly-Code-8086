PROJECT IMPLEMENTATION PLAN
===========================

1. OVERALL PROJECT REQUIREMENTS & CONSTRAINTS
---------------------------------------------
- Technology: 8086 Assembly Language, MASM, Small Memory Model.
- Architecture: Intel 8086/x86 Real Mode.
- Video Mode: VGA Mode 13h (320x200, 256 colors).
- Graphics: NO graphic libraries allowed. All rendering must use BIOS Interrupts (INT 10h) or direct Video RAM access (Segment 0xA000). Alignment with academic lectures requires using `INT 10h, AH=0Ch` for pixel drawing (or direct memory writing for optimized loops) and `INT 10h, AH=00h` for mode setting.
- Input: BIOS Keyboard Interrupts (`INT 16h`).
- Timing: `INT 15h, AH=86h` for delays (as mentioned in Graphics Lecture) or delay loops.
- Modularity: Code must be strictly divided into procedures.

2. OVERALL PROJECT PHASES (3 ITERATIONS)
---------------------------------------------
* ITERATION 1: Graphics & UI Prototype
  Focus: Static layouts, UI navigation, keyboard input handling (blocking). No gameplay logic. Six mandatory screens (Home, Name Input, Main Menu, Instructions, High Scores, Game Layout).

* ITERATION 2: Functional Game (Level 1)
  Focus: Game loop, non-blocking keyboard input (`INT 16h, AH=01h`), ball mechanics and physics, paddle movement, collision detection (pixel-color detection), brick destruction, HUD real-time updates, and lives management.

* ITERATION 3: Full Game with Advanced Features
  Focus: Multiple levels (Level 2 & 3) with increasing difficulty, level transitions, power-ups/bonus system (falling objects), and Win Screen.


ITERATION 1 DETAILED IMPLEMENTATION PLAN (5 DAYS)
=================================================
Objective: Build the visual foundation and UI flow without gameplay logic.

Day 1: Setup & Core Graphics Primitives
---------------------------------------
- Environment Setup: Ensure MASM and emulator (DOSBox/emu8086) are ready.
- Video Mode Control: Write procedures to switch to VGA Mode 13h (`MOV AX, 0013h; INT 10h`) and switch back to Text Mode 03h on exit.
- Drawing Procedures: 
  - Implement a `Draw_Pixel` procedure. (Can use `INT 10h, AH=0Ch` as per lecture for testing, but preferably write directly to `A000h` segment to establish good habits for Iteration 2).
  - Implement a `Draw_Rectangle` procedure to draw filled rectangles (useful for bricks, paddle, input boxes).
  - Implement a `Clear_Screen` procedure to erase contents between screen transitions.
- Text Rendering: Since standard BIOS text interrupts (`INT 10h, AH=09h`) only work in text mode, implement a custom bitmap font renderer using the BIOS 8x8 font table at interrupt vector 43h to render characters to the graphics screen.

Day 2: Home Screen & Name Input Screen
---------------------------------------
- Home Screen: 
  - Draw a colored/patterned background.
  - Render the game title "BRICK BREAKER" (centered, large text).
  - Draw "Press any key to continue" text.
  - Wait for any keypress (`INT 16h, AH=00h`).
- Name Input Screen:
  - Draw an input box outline and prompt ("Enter your name:").
  - Use blocking keyboard read (`INT 16h, AH=00h`) to capture user input.
  - Implement Backspace handling (erasing the last drawn character and decrementing buffer index).
  - Store valid characters in a `.DATA` buffer (max 12-15 chars).
  - Move to Main Menu on 'Enter' key.

Day 3: Main Menu & High Scores Screens
---------------------------------------
- Main Menu Screen:
  - Display options: Start Game, Instructions, High Scores, Exit.
  - Implement Up/Down keyboard navigation using arrow scan codes (`CMP AH, 48h` for Up, `50h` for Down).
  - Implement visual highlighting for the selected menu item (e.g., change background color of the text or draw an arrow).
  - Handle 'Enter' to transition to the selected screen.
- High Scores Screen:
  - Create a tabular layout: Rank | Name | Score.
  - Use hardcoded dummy static data in `.DATA` to populate at least 5 rows.
  - Add "Press any key to return" logic.

Day 4: Instructions & Game Screen Layout
---------------------------------------
- Instructions Screen:
  - Render static text explaining game rules, lives, bonuses, and controls (Left/Right to move).
- Game Screen Layout (Static only):
  - Draw the Paddle (rectangle at bottom).
  - Draw the Ball (small filled square/circle near paddle).
  - Draw the Brick Grid (nested loops to draw a 2D array of rectangles at the top with spacing and color variations).
  - Render the HUD (Heads-Up Display) at the very top (Y: 0-14):
    - Score: 0000
    - Lives: 3
    - Level: 1
    - Name: (Render the string saved from the Name Input screen).

Day 5: Integration, Code Polish & Submission Delivery
-----------------------------------------------------
- Flow Integration: Ensure smooth transitions (Home -> Name Input -> Menu -> Various Screens -> Menu -> Exit). Make sure screen clearing happens correctly between states to avoid visual artifacts.
- Code Refactoring: Ensure the code is strictly modularized into clearly named procedures with consistent indentation. Add sufficient comments.
- Documentation: Write the 5-page PDF document explaining the purpose of each screen, the navigation flow (state machine), and memory handling for the name input.
- Video Recording: Record the required 2-5 minute video demonstrating all 6 screens, name input, backspace functionality, and navigation.
